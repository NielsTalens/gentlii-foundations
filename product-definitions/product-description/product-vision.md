## Vision Statement
Gentlii aims to reduce the cognitive load and effort required for product professionals to do the thinking, planning, and information synthesis needed for solid digital product development—so they can create and trust a concise, high-quality product definition and stay aligned on outcomes.

## Needs
- Reduce cognitive load / mental overhead involved in product thinking and planning  
- Help teams gather needed information and synthesize it into a solid product definition/context  
- Increase confidence in the quality/correctness of the product definition “without any required action”

## Product Features
- Ingest/upload “all types of files” about a product/ideas as source inputs  
- Extract meaning from available data to generate key product artifacts: strategy, product vision, business case, product charter (collectively a “product description”)  
- Produce the documents in markdown and as a generated HTML page  
- Guard alignment/consistency across the generated “product description” documents  
- Validate feature requests/ideas against the product description (alignment checking)  
- Detect CRUD changes in input files and automatically run a “Product Guard” to create a report  
- Integrate into existing tools and workflows; minimize visibility/avoid being an additional standalone UI/app

**Confidence:** High  
**Evidence:** “A user uploads all types of files…” + “create: Strategy, Product Vision, Business case, Product charter… called the `product description`” + “written both in markdown as in a generated html page” + “guard alignment between all mentioned output documents” + “validate feature requests against the product description” + “If there is any change (crud) detected… Product Guard should run and create a report” + “Wherever possible the product should integrate within existing tools and workflows… Wherever we can make the product invisible we will do that.”

## Suggestion
- Define a single, concise vision statement explicitly (one sentence) to unify “reduce cognitive load,” “outcomes over output,” and “trusted product definition.”  
- Clarify primary vs secondary target users (e.g., product managers vs broader “product professionals,” and how stakeholders interact).  
- Make differentiators measurable/observable (e.g., what “opinionated product definition” includes and how “quality” is assessed).  
- Tighten the needs-to-features mapping by explicitly linking each core need (cognitive load, alignment, outcomes) to the specific capabilities that address it.
