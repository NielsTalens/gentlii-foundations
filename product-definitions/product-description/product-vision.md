## Needs
- Reduce cognitive load / lack of time and headspace for product thinking and planning.  
- Avoid building too early without enough product context (countering “spec-driven development” misapplied).  
- Shift from output-focused work to outcome-focused product development.  
- Need concise, trustworthy product definition without requiring extra user effort.  
- Need a way to check idea/feature alignment with the product definition.

## Product Features
- Ingest/upload “all types of files” that contain product information/ideas.  
- Automatically create an opinionated “product description” document set: Strategy, Product Vision, Business case, Product charter.  
- Generate outputs in Markdown and as a generated HTML page.  
- Guard/ensure alignment/consistency between the produced documents.  
- Validate feature requests (and ideas) against the product description.  
- Integrate into existing tools and workflows; minimize/avoid a standalone UI/app/account (“invisible” where possible).  
- Detect changes (CRUD) in input files to trigger guarding/updates (partially described).

## Suggestion
- Add a single, explicit one-sentence product vision statement (e.g., “Gentlii helps X achieve Y by Z”) to remove ambiguity.
- Specify the primary target persona(s) more precisely (e.g., PMs, product leads, founders, discovery teams) and the main usage context (startup vs enterprise).
- Define measurable business outcomes (e.g., reduce time-to-alignment, reduce rework, improve decision quality) and how success will be tracked.
- Clarify key workflows beyond creation (e.g., how “guarding” works, review/approval loops, notifications) at a high level.
- Explicitly state what “quality without required action” means (e.g., confidence scoring, citations, provenance, human-in-the-loop options).
